# `tomfitzhenry/linux` — `git-loom` Kernel Integration Tree

This repository maintains all custom Linux kernel patches across lab and fleet
machines on top of Linus's tree (`https://github.com/torvalds/linux`) as
independent, upstreamable feature branches woven into a single deployable
integration branch (`lab/integration`) using
[`git-loom`](https://github.com/narnaud/git-loom).

## 2. Branch Taxonomy & Design

- **Upstreamable topic branches (`upstream = true` in [`loom/loom.toml`](loom/loom.toml)):**
  - `dts/<board>`: Device tree additions and board bindings
  - `soc/<vendor>/<topic>`: SoC clock, thermal, DVFS, and platform bring-up
  - `drv/<subsystem>/<topic>`: Subsystem drivers
  - `fix/<subsystem>/<topic>`: Targeted bugfixes
  - Every commit on an `upstream = true` branch must be strictly linear, carry a `Signed-off-by:` trailer, and **never** touch CI/Nix/loom files (`README.md`, `flake.nix`, `loom/`, `.github/`).
- **Non-upstream local branches (`upstream = false` in [`loom/loom.toml`](loom/loom.toml)):**
  - `local-<topic>`: Lab-specific quirks not intended for mainline (`local-oz64-quirks`)
  - `local-ci`: Owns `README.md`, [`loom/`](loom/), [`flake.nix`](flake.nix), and `.github/workflows/`
- **Woven integration branches (generated by `git-loom`):**
  - `lab/integration`: First-parent `--no-ff` merge weave of all branches declared in [`loom/loom.toml`](loom/loom.toml) on top of `base`.

## 3. Day-to-Day Workflows

Enter the development shell (provides `git-loom`, `b4`, `dtc`, `qemu`, and `aarch64`/`armv7l` cross-compilers; `path:./loom` evaluates in <0.1s without copying the kernel tree into `/nix/store`):

```bash
nix develop path:./loom
```

### A. Consuming the Single Kernel Tree Across Machines
Downstream repositories (`robofleet`, `fleet`, `h700-harness`, `incremental-kernel-build`) consume `https://github.com/tomfitzhenry/linux` at `lab/integration` (or a pinned commit SHA from `lab/integration`) as a standard Git repository:
- **NixOS (`fleet` / `robofleet`):** Point custom kernel sources at `github:tomfitzhenry/linux/lab/integration` (or `fetchGit` on `lab/integration`) instead of maintaining per-host `boot.kernelPatches`.
- **`h700-harness` / `ikb`:** Point `kernel/linux.ref` and `ikb.json` `source` at `https://github.com/tomfitzhenry/linux.git` (`lab/integration`).

### B. Hacking on an Existing Feature Branch

```bash
# 1. Check out the topic branch (or edit on `lab/integration` and use `git loom absorb` / `git loom fold`)
git checkout dts/oz64
# ... make changes and commit with `git commit -s` ...

# 2. Verify branch hygiene and re-weave `lab/integration`
./loom/weave.sh apply

# 3. Run the build + QEMU boot verification suite
./loom/verify-kernel.sh

# 4. Push the updated branch (or open a PR targeting `lab/integration` / `local-ci`)
git push --force-with-lease myfork dts/oz64
```

### C. Adding or Dropping a Feature Branch
- **To add a branch:** Create the branch off `v7.4-rc3` (or stacked on an existing branch), add a `[[branch]]` block to [`loom/loom.toml`](loom/loom.toml) on `local-ci`, and run `./loom/weave.sh apply`.
- **To drop a branch:** Remove its `[[branch]]` block from [`loom/loom.toml`](loom/loom.toml) on `local-ci` and run `./loom/weave.sh apply`.

### D. Sending a Feature Branch Upstream with `b4`
Because every `upstream = true` branch is a pure, linear Linux commit series on top of `v7.4-rc3`:

```bash
git checkout fix/cpuidle/mvebu-l2-resume
b4 prep --enroll-base v7.4-rc3
b4 send
```

### E. Rebasing Onto a Newer Linus Tag (`torvalds/linux`)

```bash
./loom/weave.sh rebase v7.5-rc1
```

`loom/weave.sh rebase` automatically:
1. Checks `git cherry` for each feature branch against the new base and **automatically drops any branch whose commits have all landed upstream** (updating `stacked_on` references for any child branches).
2. Rebases the remaining branches in topological `stacked_on` order onto the new base.
3. Updates `base` and `[[branch]]` entries in [`loom/loom.toml`](loom/loom.toml) on `local-ci`.
4. Re-weaves `lab/integration` with `git-loom`.

### F. Running the Verification Suite Locally

- **Fast `git-loom` unit & integration tests (~20s):**
  ```bash
  nix flake check path:./loom -L
  ```
  Runs [`loom/test-weave.sh`](loom/test-weave.sh) in a hermetic sandbox (testing weave, missing `Signed-off-by:` rejection, non-kernel file rejection on upstream branches, conflict detection, and upstream rebase auto-drop).

- **Full kernel DTB + driver + QEMU boot verification (~5 min):**
  ```bash
  nix develop path:./loom --command ./loom/verify-kernel.sh
  ```
  1. Builds all 5 custom `arm64` DTBs (`sg2000-pine64-oz64.dtb`, `sun50i-h700-anbernic-rg40xx-h.dtb`, `sun50i-h700-anbernic-rg35xx-2024.dtb`, `rk3588-quartzpro64.dtb`, `rk3399-pinephone-pro.dtb`) and checks their DT properties with `fdtget`.
  2. Compiles all custom `arm64` drivers across all feature branches with `KCFLAGS="-Werror"`.
  3. Builds the `arm` kernel (`zImage`, with both SigmaStar SSC335 C212 and Marvell Armada 370 `CPU_PJ4B` / `ARCH_MVEBU` enabled) and `mstar-infinity6b0-ssc335-tapo-c212-v2.dtb` with `KCFLAGS="-Werror"`.
  4. Compiles a static `nolibc` `/init` binary and boots the woven `zImage` in `qemu-system-arm -M virt -cpu cortex-a7`, asserting `LOOM_BOOT_OK` and clean PSCI poweroff.

## 4. GitHub Actions CI ([`loom/workflows/`](loom/workflows/))

- **[`loom.yml`](loom/workflows/loom.yml) (PR gate & `lab/integration` updater):**
  - Runs on `pull_request`, `push`, and `workflow_dispatch`.
  - Executes `nix flake check path:./loom -L`, `./loom/weave.sh verify`, `./loom/weave.sh apply`, and `./loom/verify-kernel.sh`.
  - Acts as the blocking `weave-and-verify` status check on PRs and pushes the updated `lab/integration` branch when changes land.
- **[`rebase.yml`](loom/workflows/rebase.yml) (Scheduled weekly upstream rebase):**
  - Runs Mondays at 06:00 UTC (`cron: "0 6 * * 1"`) and via `workflow_dispatch`.
  - Fetches `torvalds/linux`, runs `./loom/weave.sh rebase`, runs `./loom/verify-kernel.sh`, and atomically force-pushes (`git push --atomic --force-with-lease`) all rebased branches and `lab/integration` if and only if all checks pass (opening/updating a GitHub issue on failure without touching live refs).
- **Activating `.github/workflows/*.yml` on GitHub:**
  Because the fleet `gh-via-spiffe` broker token omits the GitHub `workflows` permission, a ready-to-push commit that installs both workflows into `.github/workflows/{loom,rebase}.yml` is staged on branch `local-ci-workflows`:
  ```bash
  git -C /home/dev/src/linux-loom push --force myfork local-ci-workflows:local-ci
  gh repo edit tomfitzhenry/linux --default-branch lab/integration
  ```
